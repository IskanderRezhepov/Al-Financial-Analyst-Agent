# Moodle submission checklist

- [ ] Read README.md and tutorial_reference/PROVENANCE.md so you can explain the original tutorial and local adaptations.
- [ ] With Ollama running, start the app using `.\start.ps1` and open http://127.0.0.1:3000.
- [ ] Run `AAPL` (optionally `MSFT`) and confirm **AI report complete**, dated metrics, and all eight report sections.
- [ ] Observe that unavailable Yahoo news is explicitly marked; it is not replaced with invented news.
- [ ] Explain the optional academic underwriting flags and why a human retains decision authority.
- [ ] Use **Download evidence + report** if the lecturer requests raw source proof.
- [ ] Submit `submission.zip`, generated by `.\.venv\Scripts\python.exe package_submission.py`.
- [ ] Check Moodle's actual format/size/deadline and any requirement for a Thesys-specific demonstration.

## Package contents and status

The archive contains code, dependency locks, `.env.example`, original tutorial references, documentation,
dated public-source example reports and screenshots. It excludes `.venv`, `.git`, node_modules, `.env`,
logs, caches and ignored runtime outputs. It is prepared locally; no Moodle upload or Git commit is performed.

The local/free implementation is complete. The tutorial's authenticated Thesys C1 generation remains
unverified without your manually entered Thesys key. If the rubric explicitly requires its generated UI,
that cloud demonstration remains a manual requirement. See evidence/TEST_RESULTS.md for tested scope.
